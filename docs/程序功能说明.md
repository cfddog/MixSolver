# 主体框架说明
(1) 我想做一个结构网格+非结构网格的混合求解器。在结构网格方面采用Riemann求解器，使用opencfd的现有功能，适用于可压缩流体计算；非结构采用SIMPLE和PIMPLE计算，适用于低速和多孔介质流体计算；结构的肯定为可压缩求解器不用区分，非结构的不同的块的类型可以通过块的名称？或者单独块属性控制文件指定。
(2) 程序语言为Fortran2008语言，gcc版本11，gfortran 8.3.0
(3) 结构和非结构网格分开输入，通过设置交界面类型（interface）来进行匹配，结构求解器只当类型（gridgen generic: 8）,低速通过（fluent cas文件的的interface），并相同界面在结构/非结构网格中所属单元的对应关系，结构网格并行任按照原来的方式不用更改（），非结构网格采用Parmetis/metis进行并行分块，非结构网格整合后通过存储的界面关系设置两个块的界面边界条件。
（4）非结构网格及其并行我在UNSSolverProj已经实现，现在需要做的是结构和非结构网格重新匹配和交换。
（5）输出流场为国际单位制：结构网格的plot3d的流场文件（rho,u,v,w,t）；非结构网格通过vtk格式(rho,u,v,w,p,tf,ts)，定时保存重启文件
（6）尤其检查两个框架解算器量纲的一致性，因为无量纲方式可能不一致，交换界面信息的时候一定要注意，可以在界面先都转换为国际量纲，交换完毕后再各自转换回来。
非结构网格的zone类型：(0 "Zone 2 9220 cells 1..9220, VC: porous Fluid = 1")可以通过其中的VC类型确定，porous/fluid
设置自动保存时间，自动保存结构和非结构的流场（包含缓冲区）用于重启计算；结构流场按照节点进行插值（匹配Mesh3d.x），写作plot3d （ascii/unformatted根据mesh3d.x的格式确定）
结构解算器SST模型有bug后续解决，目前先不使用。
结构解算器后续改为Liao的格心型有限差分方法兼容目前的Riemann求解器。
非结构部分仍为实现多孔介质流体计算，通过设置VC类型（porous/fluid）来区分不同的块，后续添加相关源项和输运系数修正，用一维非平衡传热问题、二维自然热对流、二维多孔介质对流等问题进行验证。
增加gambit的neu文件格式作为非结构网格和边界条件的输入格式。
增加 低速-多孔界面的边界条件，低速可压缩界面，可压缩-多孔界面界面，界面类型根据界面两侧的块属性确定。
多孔介质验证算例包括：porous-plug, B-J problem, 二维多孔介质对流问题
